# r-dataviz-beauty-skill

> 把《R 语言数据可视化之美：专业图表绘制指南（增强版）》（张杰 著，376 页）蒸馏成一个 **可安装、可复用、所有 AI Agent 都能调用** 的 Skill。
>
> **一句话**：给数据，选图表，出可投稿的 R 代码。

```
你：我有 5 个处理组各 20 个重复的株高数据，要放进论文。
它：判断为「类别比较 + 数据分布」→ 推荐箱形图叠加抖动散点（信息量优于带误差线柱形图，p.170）
    → 给出完整可运行 ggplot2 代码（含箱形图层必须在散点图层之前，p.58）
    → theme_classic() + 学术配色 → 600 dpi / 单栏 7.5cm 的导出参数
    → 提醒样本量小时四分位数外不可靠、需叠加散点才能看出双峰
```

## 为什么做这个

这本书讲图表讲得很好，但**翻书找代码太慢**。你明明记得「有个图能表达我要的东西」，却记不住它叫什么、用哪个包、参数怎么设。

所以把书里最值得被工具化的那一项能力抽出来，做成 Skill：

- 不是书的摘要（摘要没用）
- 是**把书里的能力变成你能直接用的东西**：图表选型判断 + 可直接运行的 R 代码 + 学术配色 + 投稿级导出参数

## 它到底能干什么

### 触发场景

| 你说 | 它做 |
|---|---|
| 「我有……数据，该画什么图？」 | 先判断数据形状与表达目的，再给图，不甩代码 |
| 「用 ggplot2 画一个桑基图」 | 查配方 → 给完整可运行代码 + 包名参数 |
| 「学术图表怎么配色？」 | 按单色系 / 双色渐变系 / 多色系三原则给色值与调色板 |
| 「黑白印刷怎么办？」 | 给出灰度 + 形状替代方案 |
| 「投稿要求 600 dpi 怎么设？」 | 给 dpi / 格式 / 尺寸 / 字号 / Cairo 导出代码 |

### 覆盖范围

**9 大类、139 个图表条目**：类别比较（柱形图/雷达图/词云图…）、数值关系（散点/气泡/相关系数图/韦恩图…）、数据分布（直方图/核密度/箱形图/小提琴图/峰峦图…）、时间序列（折线/日历图/螺旋图/地平线图…）、局部整体（饼图/马赛克图/华夫饼图…）、高维（PCA/t-SNE/热力图/平行坐标系/RadViz/切尔诺夫脸谱图…）、层次（矩形树状图/旭日图/圆堆积图…）、网络（和弦图/桑基图/边绑定图…）、地理空间（分级统计地图/流向地图/Voronoi/地铁线路图…）。

### 三条它比"直接问大模型"强的地方

1. **不会编造不存在的包和函数**。书里用什么就写什么——雷达图是 `fmsb::radarchart()`，不是你可能猜的 `ggradar`；词云是 `wordcloud`，不是 `ggwordcloud`。书里没出现的包名被单独列进附录，明确禁止引用。
2. **结论都带原书页码**，你可以回查核对。
3. **带着"什么时候不该用"的判断**。比如：极坐标适合周期性数据、不适合连续时间趋势 (p.48)；饼图很难精确比较各部分大小 (p.82)；气泡必须按面积而非半径映射 (p.129)。

## 它是怎么做出来的（完整流程）

用的是 WorkBuddy 的 **`book-to-skill`（一本书转一个 Skill）** 技能，走它规定的 6 步工作流：选书定义"一件事" → 抽取知识骨架 → 选 Skill 类型 → 撰写内容 → 自检 → 封装。

### 第 0 步：定义"一件事"

一个 Skill 只解决一件事。这本书最值得被工具化的能力定为：

> 根据用户的数据结构与分析目的，选定图表类型，产出可直接运行的 R/ggplot2 代码（含配色与投稿级导出参数），并说明为什么。

Skill 类型：**Applier（框架应用器）** + **Decision-Tree（决策树）**。

### 第 1 步：PDF 文本提取

原书 29 MB、376 页、文本层完整（非扫描件）。用 `pypdf` 提取：

```bash
python tools/extract.py
# → pages: 376 / chars: 383,107 / code_markers: 978
```

输出 `book_text.txt`，每页以 `===== PAGE N =====` 分隔。

### 第 2 步：按印刷页码切章

**关键坑**：PDF 页码 ≠ 印刷页码。本书偏移量为 **12**（PDF 第 14 页 = 书页 2）。
按目录换算后切成 12 个章节文件：

```bash
python tools/split.py
# → ch01 75092 / ch02 7216 / ch03 23864 / ... / ch12 26801 字符
```

每段插入 `<<<BOOKPAGE N>>>` 标记（N = 印刷页码），保证后续所有引用都能定位到纸质书。

### 第 3 步：6 个子 Agent 并行精读

一本书 38 万字，单个上下文读不完也读不精。按章节拆给 6 个子 Agent **并行**精读，每个负责 2 章，输出结构化笔记：

| Agent | 章节 | 产出 |
|---|---|---|
| 1 | 第 1–2 章 | 六大类图表体系、ggplot2 语法速查、配色原理与全部 HEX 色值、数据处理 |
| 2 | 第 3–4 章 | 类别比较型 + 数值关系型：29 个图表条目 |
| 3 | 第 5–6 章 | 数据分布型 + 时间序列型：分布图选型决策树、时序图分流规则 |
| 4 | 第 7–8 章 | 局部整体型 + 高维数据：饼图否定性判断、维度规则 |
| 5 | 第 9–10 章 | 层次关系型 + 网络关系型：ggraph 布局体系 |
| 6 | 第 11–12 章 | 地理空间型 + 学术规范：全部 dpi/cm/pt/MB 数字 |

给子 Agent 的硬性约束（决定了最终质量）：

- 必须用 Read 读原文，**不许凭记忆编造**
- 代码片段必须来自原文，不改写函数签名
- 每条事实性陈述都要 `(p.页码)`
- **书中没出现的内容要显式标注**——这条最重要，它直接产出了「未出现的包名附录」

> 这个约束很有效。比如任务提示里我预设了 `ggradar`/`ggwordcloud`/`fastPCA`/`packcircles`，子 Agent 逐个核查后报告"原文均未出现"，避免了 Skill 生成不存在的函数。

### 第 4 步：合并重组为参考文档

再用 1 个子 Agent 把 5 份笔记**搬运 + 结构化重组**（不是压缩，代码块与页码全保留），产出 `chart-recipes.md`；第 1–2 章笔记按主题拆成 3 份；第 12 章单独成 `academic-publishing.md`。

```bash
python tools/build_refs.py
```

### 第 5 步：写 SKILL.md 并按清单自检

按 `book-to-skill` 的自检清单逐条核对：

- [x] 只做一件事，一句话说清用途
- [x] 有明确触发场景与入口示例
- [x] 知识来自本书、有 `(p.页码)` 出处
- [x] 含 3 个 few-shot，覆盖典型输入与超范围边界
- [x] 有失败兜底（数据不足怎么问、超范围怎么答、图片化内容缺失怎么补）
- [x] 一句话说明 ≤ 30 字：「给数据，选图表，出可投稿的 R 代码」（17 字）

### 第 6 步：封装

落为 `SKILL.md`（含 YAML frontmatter + `agent_created: true`），放进 `~/.workbuddy/skills/r-dataviz-beauty/`。用户级目录 = 所有 Agent 可用。

## 提取脚本怎么用

想对别的书做同样的事，流程可以直接复用：

```bash
# 1. 准备环境
python -m venv .venv
.venv/Scripts/pip install pypdf        # Windows
# .venv/bin/pip install pypdf          # macOS/Linux

# 2. 提取（改 extract.py 里的 src / out 路径）
python tools/extract.py

# 3. 切章（关键：先确认 PDF 页码与印刷页码的偏移量）
#    本书 = 12，即 PDF 第 N+12 页对应书页 N
python tools/split.py

# 4. 之后交给子 Agent 精读 → 合并 → 写 SKILL.md
```

**复用时的两个提醒**：

1. 偏移量每本书不同，先翻几页确认再切，否则所有页码引用都会错。
2. 扫描版 PDF 没有文本层，`pypdf` 提取为空，需要先 OCR。

## 已知边界

- **只讲 R**。Python/Matlab/Origin 绘图超出范围，会明确说明并建议替代。
- **不做统计分析本身**。不建模、不做显著性检验、不解释业务结论——只负责"怎么把图选对、画对"。
- **图片化内容缺失**。书中图 1-7-20~24 的单色/双色渐变色块是图片，文本层无色值；此时改用 `RColorBrewer` / `viridis` / `ggsci` 取色并说明原因。
- **部分包名书中未出现**（已在附录标注）：`ggradar`、`ggwordcloud`、`ggcorrplot`、`ggVennDiagram`、`ggpubr`、`paletteer`、`dendextend`、`tidygraph`、`packcircles`、`leaflet`、`getData()`。替代方案一律以原文为准。
- **地图合规**：涉及向社会公开的地图时会提示《地图管理条例》第十五条的地图审核制度。
